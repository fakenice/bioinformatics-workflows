# FlowSeq Evaluation Report v1.0.0

**Status**: filled from committed run artifacts by `evaluation/metrics/render_report_from_results.py`. This file used to be an empty template while `README.md` quoted numbers; that contradiction is what this render fixes.

**What is compared** (same settings as README §Evaluation): the same local model (`qwen3:14b` via Ollama, `think=False`, `temperature=0.3`) on 20 test cases, **Prompt + Skill** (SKILL.md as system prompt) vs **Prompt Only** (neutral system prompt), both on the no-internet baseline, so SKILL.md is the only difference.

**Not recorded**: the run artifacts contain no timestamp, so the wall-clock date of the run is not asserted anywhere in this report. The raw model outputs (`outputs_qwen3_14b.json`, `outputs_qwen3_14b_noskill.json`) are committed next to the reports, so every score below can be recomputed independently.

## 1. Pipeline Selection Accuracy

- Prompt + Skill: 18/20 cases correct (90.0%); misses: TC-009, TC-017
- Prompt Only: 17/20 cases correct (85.0%); misses: TC-002, TC-009, TC-017

The two arms differ by **one case out of 20** (TC-002 is the only case the Prompt-Only arm misses and the Skill arm gets right). Both arms miss TC-009 and TC-017. A single-case difference is not a measurable effect; the README's +5.0 pt should be read as 'no reliable difference', not as a capability gain.

## 2. Knowledge Grounding Rate

- Prompt + Skill: 12 ungrounded citations out of 380 (96.8%); ungrounded rate 3.2%
- Prompt Only: 21 out of 347 (94.0%); ungrounded rate 6.0%

This is the metric with the largest usable denominator, and the arm difference is 9 citations out of a few hundred.

Grounding is checked against the committed knowledge base: 122 tool names, 28 DOIs, 88 URLs.

## 3. Parameter Correctness

- Prompt + Skill: 15 parameters checked, 0 invalid (100.0%)
- Prompt Only: 3 checked, 0 invalid (100.0%)

**Small denominators**: 15 and 3 parameters. Both 100% scores mean 'no violation was found in a handful of extractable parameters', not 'parameter generation is correct'. The asymmetry (15 vs 3) also mirrors the arms' output verbosity, so this metric is not comparable across arms in the usual sense.

## 4. Reference Coverage

- Prompt + Skill: 17/19 expected authoritative sources present (89.5%)
- Prompt Only: 13/19 (68.4%)

This is where the Skill's contribution is clearest: the same 19 expected sources, and the Skill arm names 4 more of them. Same denominator, real counts.

## 5. Schema Validity

- Prompt + Skill: 0/0 JSON outputs parsed and validated (score recorded as 100.0%)
- Prompt Only: 0/0 (score recorded as 100.0%)

**Degenerate on this run**: zero structured-JSON outputs were produced by either arm, so the stored 100% is a default for 'nothing to check', not evidence of schema compliance. It is retained in the Overall mean only because that is how the committed report files compute it; it must not be quoted as a result.

## 6. Workflow Completeness (separate script)

- Prompt + Skill: 62/82 standard steps across 18 pipeline cases (75.6%)
- Prompt Only: 59/82 across 18 cases (72.0%)

Evaluated by `python/evaluation/metrics/workflow_completeness.py` against the standard step lists in the pipeline definitions (82 steps total). Not part of the 5-metric Overall mean.

## 7. Expert evaluation

**Not conducted.** No human review of these outputs took place, so the rubric in the old template is not a result and is deliberately left unfilled here.

## Caveats for anyone citing these numbers

1. Single run, one model (`qwen3:14b`), one decoding setting: no repeated sampling, so arm differences of one case cannot be separated from run-to-run noise.
2. `Schema Validity` is 0/0 and `Parameter Correctness` rests on 15 vs 3 checks; the Overall mean therefore contains two near-empty 100% terms.
3. Selection Accuracy differs by one case out of 20.
4. Reference Coverage (17/19 vs 13/19) and Knowledge Grounding (12/380 vs 21/347 ungrounded) are the two rows with comparable denominators; they are the defensible ones.
5. `report.json` (overall 0.9823) and `comparison_report_final.json` in the same folder are different runs and must not be mixed with the table above.
