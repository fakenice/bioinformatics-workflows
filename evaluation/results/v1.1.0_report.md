**Status**: regenerated on 2026-11-02 from the committed run artifacts (`python/evaluation/results/outputs_qwen3_14b.json` and `outputs_qwen3_14b_noskill.json`). `v1.0.0_report.md` is kept unchanged for provenance; this version supersedes its scoring semantics.

## What changed from v1.0.0

1. **Pipeline accuracy uses 18 cases, not 20.** TC-014 and TC-017 have no expected pipeline; they are out-of-scope cases and are scored separately as abstention behaviour.
2. **A missing prediction is `unparsed`, not a correct abstention.** v1.0.0 counted TC-014 as correct because both the expected label and the missing prediction were `None`. Abstention now requires an explicit `__uncovered__` marker.
3. **Zero-denominator metrics are excluded from the overall.** Schema validity is 0/0 on this run and is reported as N/A; v1.0.0 averaged it in as 100%.
4. **Uncertainty is reported.** Wilson 95% intervals, an exact McNemar test on the paired pipeline cases, and a minimum-detectable-difference floor are included.

## 1. Pipeline Selection Accuracy

- Prompt + Skill: 17/18 (94.4%), Wilson 95% CI 74.2%–99.0%
- Prompt Only: 16/18 (88.9%), Wilson 95% CI 67.2%–96.9%
- Skill-only correct: TC-002; baseline-only correct: none
- Exact McNemar p = **1.000** on 1 discordant case(s).
- Minimum detectable difference floor at n=18: **29.3 pt** (two independent proportions, alpha=0.05, power=0.8).

The arms differ by one case (TC-002). The intervals overlap almost completely and the paired test is not significant; this run does **not** demonstrate a pipeline-selection gain. It also cannot rule out a difference smaller than the MDE floor above.

## 2. Out-of-scope behaviour (separate from pipeline accuracy)

- Prompt + Skill: 0/2 explicit abstentions; TC-014=unparsed; TC-017=answered (scrna-seq)
- Prompt Only: 0/2 explicit abstentions; TC-014=unparsed; TC-017=answered (scrna-seq)

Both arms answered the out-of-scope questions instead of declining: TC-014 produced no extractable pipeline id (unparsed), and TC-017 was mapped to `scrna-seq`. These outputs may predate the repository's zero-result protection commit; do not quote this as the current behaviour without regenerating the outputs.

## 3. Knowledge Grounding Rate

- Prompt + Skill: 12 ungrounded entities out of 380 (96.8%).
- Prompt Only: 21 out of 347 (94.0%).

The denominators differ because the arms cite different numbers of entities (380 vs 347); the comparison is a rate, not a fixed set of citations.

## 4. Parameter Correctness

- Prompt + Skill: 15 parameters checked, 0 invalid.
- Prompt Only: 3 checked, 0 invalid.

Both arms score 100%, but the denominators are 15 vs 3. This means no violation was found among the extractable parameters, not that parameter generation is correct; the asymmetry mirrors output verbosity and makes the arms non-comparable on this metric.

## 5. Reference Coverage

- Prompt Only: 13/19 (68.4%).

This is the clearest signal in the run: the same 19 expected sources, with 4 more named by the skill arm. It is a local, single-model result and not a general guarantee.
